# 管理端物理删除设计

## 目标

超级管理员可从账号管理和房间管理中物理删除目标账号或目标房间。删除必须在一个数据库事务中完成，只清除目标专属数据，绝不删除其他账号或其他房间的记录。

## 约束与删除边界

房间是游戏记录的归属边界。删除一个房间时，清除其成员、玩家、资产、请求、流水、账本、回合、事件、债务、审计、换角请求、结算及关联子项；共享的账号、人物和地产定义保留。

账号可被删除的前提是它没有被任何保留房间引用，且不是任何保留房间的创建者、结算操作者、结算参与者或安全日志引用者。若账号只关联可一并删除的房间，管理员应先删除这些房间，再删除账号。服务端以稳定的 `ACCOUNT_DELETE_BLOCKED` 错误拒绝其余情况，避免破坏他人房间或历史。

超级管理员不得删除自身，也不得删除其他超级管理员，分别返回 `CANNOT_DELETE_CURRENT_ACCOUNT` 和 `CANNOT_DELETE_SUPER_ADMIN`。房间和账号不存在时按现有资源不存在语义返回 404。

## API 与服务

新增下列仅限超级管理员的幂等写接口：

- `DELETE /api/admin/rooms/:id`
- `DELETE /api/admin/accounts/:id`

每个请求沿用现有 `Idempotency-Key` 与 `executeIdempotent` 约定。服务层新增两个专用删除方法：先在 Serializable 事务中读取并验证目标及保护条件，再严格按 `roomId` 或 `accountId` 删除关联行，最后删除根记录。不得使用未带目标条件的 `deleteMany`，不得改动其他管理操作的语义。

删除账号前，服务必须返回实际撤销的 session ID；路由在事务提交后调用现有 Socket 会话撤销逻辑，使已登录目标账号立即退出。删除房间提交后通知该房间当前版本，使客户端刷新并回到房间列表。

任何失败都回滚整个事务。成功响应返回 `{ deleted: true, id }`；幂等重放复用首个成功结果，不再次删除或通知。

## 管理界面

账号详情中在现有“禁用账号”后加入红色 `删除账号` 按钮；房间详情中在“强制结束”后加入红色 `删除房间` 按钮。按钮复用当前 `ConfirmDialog`、`danger-button`、忙碌状态和错误展示，保持现有后台风格。

确认弹窗明确说明不可恢复以及清除范围，并要求输入目标用户名或房间名称。只有准确匹配时，`确认删除` 可点击。确认后使用相应 DELETE 接口；成功时关闭详情、清空草稿、刷新后台列表与看板。接口拒绝时保留详情与输入，显示服务端错误。

## 测试

API 集成测试覆盖：

- 删除房间会删除该房间所有专属记录，保留其他房间、账号和主数据。
- 删除受保留房间引用的账号被拒绝，数据完全不变。
- 删除未引用的普通账号会删除账号及会话，并立刻断开其 Socket。
- 删除自身与删除超级管理员均被拒绝。
- 未授权、缺失目标、事务失败和幂等重放遵循既有错误及幂等契约。

Playwright 覆盖账号与房间详情中的删除按钮、名称确认门槛、正确的 DELETE 请求、成功后的列表刷新及拒绝后的错误可见性。

## 自检

删除范围按 `roomId` 或 `accountId` 定位，账号删除的共享引用被提前拒绝，避免跨房间或跨账号删除。接口、Socket 处理、UI 和测试对幂等与失败回滚使用同一语义，范围限定为管理端物理删除。

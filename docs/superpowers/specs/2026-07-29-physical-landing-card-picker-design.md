# 实体落点地产卡片选择器设计

## 目标

将玩家工作台“声明实体落点”中的原生地产下拉框替换为可搜索、可点击选择的地产卡片列表。卡片复用全局地产清单的价格、租金、建筑和归属信息，帮助玩家在实体棋盘游戏中快速核对并声明停留地产。

## 范围

- 仅修改玩家端工作台的“声明实体落点”面板。
- 保留既有 `POST /api/rooms/:roomId/landings` 请求和 `propertyName` 参数。
- 不修改后端落点、购买、建造或产权校验。
- 不替换其他业务面板中的地产下拉框。

## 交互

1. 打开面板时，显示搜索输入框、已选地产摘要和全部地产卡片。
   现有标题、说明文字“请选择棋子精确停留的地产。系统不会追踪棋盘位置。”和酒红色“确认落点”主按钮必须保留。
2. 输入名称可即时按地产名称筛选；无匹配时显示空状态。
3. 点击任一地产卡片更新当前 `landing` 值，并以高亮边框及勾选图标标识选中卡片。
4. 已购、无主和已抵押均是展示信息，不禁用卡片，也不改变选择或提交条件。
5. 点击“确认落点”后，继续调用现有 `confirmLanding`；成功行为保持为关闭面板、记录可信落点、显示等待银行确认的通知。

## 卡片内容与状态

每张卡片显示：地产名称、购买价、当前过路费、建筑等级和所有者。

- `ownerId` 能对应当前玩家时，右上角以高对比状态角标显示“已购”，并展示该玩家名称。
- `ownerId` 为空或没有对应玩家时，显示“无主”。卖给银行后会因 `ownerId` 为空自动恢复该状态。
- 开局赠送的地产已有 `ownerId`，因此自动显示“已购”。
- `mortgaged` 为真时，额外显示“已抵押”说明。

## 布局与可用性

- 面板内卡片区域可独立滚动，桌面端使用多列网格，窄屏收为单列。
- 选中状态不能仅依赖颜色，应同时显示勾选图标和可读文本。
- 搜索框具有明确标签；卡片使用按钮语义，支持键盘聚焦、Enter 和 Space 选择。
- 确认按钮保持原有禁用条件：忙碌中或尚未选择地产时不可提交。

## 验证

- 为纯函数筛选和产权状态判定补充单元测试。
- 为玩家端组件补充或扩展现有端到端测试，验证搜索、点击已购卡片、选中反馈和提交请求。
- 执行 Web 构建及相关测试，并在浏览器中检查桌面与移动视口。

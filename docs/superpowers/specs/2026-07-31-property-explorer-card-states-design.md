# 地产搜索、筛选与卡片状态设计

## 目标

在玩家端、银行端和声明落点中继续复用现有 `LandingPropertyCardPicker`，统一搜索、筛选、产权信息和地产卡视觉状态，同时用模式参数明确区分“浏览详情”和“选择落点”。本次只调整前端共享组件、辅助函数、样式和测试，不修改 API 或数据库结构。

## 入口与模式

共享组件保留两种模式：

- `browse`：用于玩家端“我的地产 / 全局地产”和银行端“全地图地产”。点击整张卡展开详情，再次点击收起。展开不产生红框或红勾。
- `landing`：用于声明实体落点。点击整张卡只更新落点选择，使用红色轮廓和红色勾选标记，不提供详情展开。

组件新增可选 `viewerPlayerId`。玩家端浏览入口传入当前玩家 ID，用于把自己的地产标记为“我的地产”；银行端和声明落点不传，已占有地产统一标记为“已持有”。

## 搜索与筛选

搜索在地产名称、所有者角色名和玩家昵称中匹配，并继续使用现有 `pinyin-pro` 能力支持：

- 中文连续子串；
- 全拼连续子串；
- 拼音首字母；
- 中文与拼音混合输入；
- 忽略空格与英文大小写。

地产模块和声明落点显示同一组控件。筛选标签顺序为“全部、无主、当前房间内已选择的角色”。角色标签只显示角色名，不显示玩家昵称。

筛选状态必须明确区分三种值：全部、无主、指定玩家，不能继续用 `null` 同时表示“全部”和“无主”。搜索关键词与所有者筛选取交集。筛选后仍保持已占有地产优先、国库地产靠后的稳定排序。

## 产权与所有者

卡片右上角产权标签规则：

- 玩家端浏览自己的地产：“我的地产”；
- 其他已占有地产：“已持有”；
- 无主地产：“国库”。

所有者区域使用两行：第一行角色名，第二行灰色 `「玩家昵称」`。无主地产显示“无主”，下一行显示灰色 `「银行」`。历史数据找不到有效角色时使用中性黑色主题，并显示可用的玩家名称或“未知角色”。

角色主题色为：

- 宜修：浅蓝色；
- 甄嬛：淡黄色；
- 年世兰：淡紫色；
- 沈眉庄：淡玫红色；
- 安陵容：淡绿色；
- 国库或异常数据：黑色。

卡片边框使用完整主题色，左边框加粗。产权标签和角色筛选标签使用约 20% 的主题色浅填充；“全部”使用约 12% 的黑色浅填充；“无主”筛选标签使用白色。筛选标签不显示主题色左竖线。

## 卡片状态

非展开卡具有稳定的统一宽高，附加元素不得改变尺寸。桌面网格保持固定卡片宽度范围；筛选后只有一张卡时保留右侧空白，不拉伸占满整行；移动端空间不足时回落为整行宽度。空搜索结果虚线框与普通非展开卡同宽同高。

冷宫状态由所有者的 `tollCollectionBlocked` 决定。提示“冷宫 · 免过路费”显示在宫殿名称右侧，固定单行，并为右上角产权标签预留空间。当前过路费显示为 0。

抵押状态由地产的 `mortgaged` 决定。整张卡使用确认过的半透明效果，卡面叠加放大后的红色矩形“已抵押”印章，逆时针倾斜 45 度；不再显示右下角抵押标签。印章必须保持在卡片边界内。冷宫与抵押可以同时展示。

后端规则要求抵押前卖掉全部建筑，因此真实系统中的抵押地产只能是 0 级。视觉稿里的“抵押 + 3 级”只用于检查排版，不向系统引入无效状态。

## 浏览展开详情

`browse` 模式移除“查看完整价格与租金”按钮。卡片本身作为可聚焦、可键盘操作的展开控件，并通过 `aria-expanded` 暴露状态。

展开区域自动在基础信息下方加入分割线，内容包括：

- 价格信息：购买 / 卖回价、抵押价、建筑费、建筑出售价，以 2 x 2 四宫格显示；每格标题在左、金额在右。
- 建筑等级过路费：0 至 3 级以 2 x 2 四宫格显示；大宫殿拆为下方独立模块，与四宫格保留小间距。
- 大宫殿模块使用主题色双线边框和极浅主题色背景，金额右对齐。

展开卡根据详情自然增加高度，不使用声明落点的红色选择轮廓或勾选标记。已抵押卡展开后继续保持半透明，印章固定在基础信息区域，不遮挡详情宫格。

## 声明落点

`landing` 模式不渲染详情区域，也不响应展开操作。当前选择使用红色轮廓和红色勾选图标，角色主题色左边框继续保留，红色选择状态不得覆盖主题边框。

声明落点支持普通、冷宫、抵押、冷宫与抵押并存等真实组合状态。组合状态不改变卡片尺寸。

## 状态与数据流

搜索词、所有者筛选和浏览展开状态保留在共享组件本地：

- 搜索或筛选只派生可见地产列表，不修改房间快照；
- 浏览展开状态按地产名称维护，多张卡可以独立展开；点击同一卡片只切换该卡；
- 声明选择仍由父组件传入 `value` 和 `onChange` 管理；
- 所有角色、产权、主题、冷宫和过路费信息均从当前房间快照派生。

不新增网络请求。若当前筛选目标离开房间或不再拥有有效角色，组件应回退到“全部”，避免保留不可见筛选条件。

## 可访问性与边界情况

- 搜索框保留明确的可访问名称和搜索图标；
- 筛选按钮使用 `aria-pressed`；
- 浏览卡使用 `aria-expanded`，支持回车和空格切换；
- 声明卡使用 `aria-pressed`；
- 抵押、冷宫、产权和所有者信息包含在卡片可访问名称中；
- 长名称和金额不得遮挡、溢出或改变非展开卡尺寸；
- 无主、无结果、未知角色和空玩家列表均有稳定回退显示。

## 测试与验收

辅助函数单元测试覆盖中文、全拼连续子串、首字母、混合输入、大小写、空格、无主筛选、玩家筛选和稳定排序。

组件测试覆盖：

- 只渲染当前房间有效角色及白色“无主”标签；
- 玩家端“我的地产”和银行端“已持有”；
- 角色名与灰色 `「玩家昵称」`、无主与 `「银行」`；
- `landing` 只选择且无详情，`browse` 整卡展开且无红色选择状态；
- 冷宫、抵押、冷宫与抵押并存；
- 价格四宫格、等级四宫格和独立大宫殿模块；
- 空结果和普通卡尺寸一致。

样式测试覆盖浅色主题填充、统一圆角、固定非展开尺寸、单卡不拉伸、抵押印章、冷宫单行提示、详情网格和移动端回退。

完成后运行相关 Vitest、样式契约测试、类型检查和构建。按仓库要求只通过 Docker Compose 启动实际系统，并在 `http://localhost:3000` 验证玩家端、银行端和声明落点的桌面及移动端效果。

# 全局路由骨架屏与旧页面闪现修复设计

## 背景

当前每个 Next.js 页面都会重新挂载 `AppRouterClient`。页面切换通过按钮调用 `router.push` 或 `router.replace`，目标路由提交前，Next.js 会继续显示旧路由；目标组件挂载后还会把 `account` 初始化为 `null`，重新请求 `/api/auth/me`。因此登录进入房间列表时会出现“登录页 -> 加载图标 -> 房间列表”，其他页面切换也可能短暂保留上一页面。

浏览器检查未发现 hydration、控制台或 API 异常。本次只修复路由视觉过渡，不改变认证、授权、Cookie、数据库或 Socket.IO 行为。

## 目标

- 覆盖所有需要登录的页面，包括房间列表、创建房间、房间身份与操作页面、个人中心和超管页面。
- 发起客户端路由跳转后，在下一次浏览器绘制前隐藏旧页面内容。
- 目标路由身份恢复和首批数据加载期间显示一致的移动端优先骨架屏。
- 覆盖按钮导航、首次打开受保护页面、浏览器前进后退以及未缓存路由。
- 网络异常时不能永久停留在骨架屏。

## 非目标

- 不把认证迁移到 Next.js middleware 或服务端组件。
- 不重构现有 API 会话模型，也不改变设备令牌恢复规则。
- 不在本次改造中引入全局 Auth Provider、数据缓存库或新的状态管理依赖。
- 不改变任何业务页面的数据加载顺序和权限判断结果。

## 方案

### 统一骨架组件

新增可复用的 `RouteSkeleton` 客户端无关展示组件。它使用现有米白、暗红、鎏金视觉变量，包含：

- 顶部身份与余额区域的稳定占位块；
- 页面标题和主要操作区域占位；
- 适合房间、管理和详情页面的列表行占位；
- `role="status"`、`aria-busy="true"` 和仅供读屏器读取的“页面加载中”。

骨架不显示业务数据，不使用会造成布局跳动的随机尺寸。所有尺寸使用固定值和响应式约束；触控布局按移动端优先设计。动画只使用轻量透明度变化，并在 `prefers-reduced-motion: reduce` 下关闭。

### 客户端导航遮挡

`AppRouterClient` 新增本地 `routePending` 状态。统一的 `go()` 在调用 `router.push/replace` 前先把该状态设为 `true`。渲染分支最前方优先返回 `RouteSkeleton`，因此登录页或其他旧页面会在路由请求期间立即被遮挡。

为避免同地址导航卡住，`go()` 在目标地址与当前 `pathname + search` 完全一致时不进入等待状态。导航开始后启动 10 秒看门定时器；若目标路由未完成挂载，看门定时器解除骨架并显示“页面加载较慢，请重试”的非破坏性提示。组件卸载时清理定时器。

目标页面挂载后会创建新的 `AppRouterClient`。对于受保护页面，只要 `authChecked` 尚未完成或 `account` 尚未恢复，同样返回 `RouteSkeleton`，从而让旧页面遮挡与身份恢复之间保持连续，不出现空白帧。

直接打开 `/login` 时仍立即显示登录表单。登录页只有在已经发起离开该页的路由跳转后才显示骨架。

### Next.js 路由回退

新增根级 `app/loading.tsx`，复用 `RouteSkeleton`。它负责覆盖 Next.js 路由段尚未提交的情况，包括浏览器前进、后退、首次进入未缓存页面以及框架级异步路由加载。

`loading.tsx` 与 `AppRouterClient` 内部骨架使用同一组件和样式，避免两个加载阶段视觉不一致。

### 数据加载

登录成功后继续使用服务端 Cookie 作为唯一会话依据。目标房间列表页负责加载房间数据；旧登录组件不再在触发导航后重复请求房间列表。此调整只消除重复请求，不改变房间列表 API、合并逻辑或错误处理。

## 状态顺序

正常登录跳转：

1. 登录接口成功并设置当前账号。
2. `go('/rooms', true)` 同步进入 `routePending`。
3. 旧登录表单被 `RouteSkeleton` 替换。
4. Next.js 提交 `/rooms` 路由。
5. 新页面在 `/api/auth/me` 完成前继续显示 `RouteSkeleton`。
6. 身份恢复完成，房间列表页面渲染并加载房间数据。

未登录直接访问受保护页面：

1. 受保护页面先显示 `RouteSkeleton`。
2. `/api/auth/me` 返回未登录。
3. 路由替换到 `/login?next=...`。
4. 登录页直接显示表单，不显示错误的受保护页面。

## 错误处理

- 身份失效仍走现有 `invalidateLogin()`，最终进入登录页。
- 路由等待超过 10 秒时解除遮挡并提示重试，避免永久阻塞。
- 路由切换期间不取消已经提交的业务请求，也不修改幂等键。
- 骨架组件不捕获错误；现有 API 错误、403 和房间错误页面继续负责最终反馈。

## 测试

### 单元与契约测试

- `go()` 在 `router.push/replace` 前进入路由等待状态。
- 同地址导航不会进入永久等待。
- 受保护页面在 `authChecked=false` 时渲染统一骨架。
- 登录页初次访问仍渲染登录表单。
- 10 秒看门定时器会恢复可操作界面并给出提示。
- `RouteSkeleton` 具备稳定结构、可访问状态和减少动画样式。

### 浏览器测试

- 延迟目标路由或身份接口时，登录表单在提交成功后立即消失，期间只显示骨架。
- 房间列表、个人中心、管理页和房间内页面之间切换不再显示上一页面内容。
- 浏览器前进和后退显示骨架或目标页面，不显示错误的旧页面。
- 桌面、Android、iPhone 和短屏移动端无横向溢出或文本遮挡。

## 验收标准

- 从登录页进入房间列表时，登录表单不会在登录成功后再次可见。
- 所有登录后页面切换期间只出现统一骨架或目标页面。
- 页面刷新、前进和后退不会暴露不属于目标路由的旧内容。
- 未登录访问受保护页面仍正确跳转登录页并保留 `next`。
- 登录、权限、房间操作、Socket 重连和幂等行为保持不变。
- 失败导航不会让页面永久卡在加载状态。

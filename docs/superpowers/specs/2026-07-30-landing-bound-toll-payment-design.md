# 落点绑定的过路费支付

## 目标

将“支付过路费”从“资产操作”中拆出，作为玩家端高频快捷模块，并自动以当前玩家本回合已确认、剧情已结算的地产落点作为唯一结算目标。玩家不再选择地产。

## 范围

- 在快捷操作中新增“支付过路费”，位置在“资产操作”之前；其余快捷模块按现有顺序后移。
- 模块直接显示当前落点地产、地主、地产等级及应付过路费，并只提供一次确认支付操作。
- 当前无法支付时，模块仍可打开，支付按钮禁用并显示具体原因。
- 从“资产操作”中移除“支付过路费”选项及其专用状态、筛选、金额预览和提交分支。
- 保持现有过路费支付 API 和服务端落点校验，不新增支付接口或数据库结构。
- 在既有房间快照的落点数据中增加只读 `tollSettled` 标记，使刷新后仍能明确展示“本次过路费已经结算”。

## 非目标

- 不改变落点声明、银行确认、剧情结算或回合结束规则。
- 不改变过路费金额、抵押地产免收、冷宫地主免收或华妃过路费加成规则。
- 不改变资产操作中的出售建筑、抵押、赎回、卖回银行和玩家间交易流程。
- 不改变转账与银行付款申请流程，尤其不改变沈眉庄剧情罚款减免的金额计算与开关。

## 架构与数据流

玩家端沿用已有 `currentLanding`、`landingConfirmed` 与 `landingProperty` 推导当前可见落点。服务端快照为每个可见落点派生 `tollSettled`：仅当该落点对应的既有过路费结算记录仍处于已提交状态时为真；结算被冲正后恢复为假。独立过路费模块基于这些值和快照中的玩家、地产数据生成只读结算视图：

1. 没有已确认且剧情已结算的地产落点时，显示“请先声明地产落点，并由银行确认剧情已结算”。
2. 已确认落点不是他人未抵押地产时，显示对应原因：无主、自己持有、已抵押、地主冷宫中或已结算。
3. 满足条件时，使用该落点地产计算金额，展示地产、地主、等级和应付金额，并启用支付按钮。
4. 提交时，以 `landingProperty.name` 构造既有 `POST /api/rooms/:roomId/properties/:propertyName/toll` 请求。提交成功后保留当前回合的实体落点信任状态、关闭模块并显示结算完成提示；这样再次打开模块时可从快照的 `tollSettled` 显示已结算并禁用。新落点声明或回合变化会替换该状态。

服务端继续在 `payToll` 中查询该玩家对应的确认落点，并验证其 `propertyId` 与路径中的地产一致。客户端自动选择只提升可用性，服务端仍是业务正确性的最终边界；`tollSettled` 只用于展示和禁用，不代替提交时的校验。

## 组件边界

- `PlayerView`：推导过路费结算状态，渲染快捷入口和独立操作面板，提交既有请求。
- 资产操作面板：仅保留资产处置和交易，不再依赖过路费模式。
- `PrismaGameService.snapshot`：从既有过路费结算记录派生每个落点的 `tollSettled` 状态。
- 既有 `PrismaGameService.payToll`：维持金额计算、资格校验、幂等与入账，不修改行为。

## 不可支付状态

模块入口始终存在；仅支付按钮会在 `busy` 或以下任一业务原因出现时禁用：

- 无确认且剧情已结算的地产落点。
- 落点地产不存在、无主或归当前玩家。
- 落点地产已抵押。
- 地主处于阻止收取过路费的冷宫停轮状态。
- 当前落点过路费已经结算。

按钮下方显示单一、确定的原因。客户端提示用于操作引导；提交后端仍可能因并发状态变化返回既有错误码。

## 兼容性

沈眉庄的 `plotFineReduction` 仅影响转账场景中勾选的剧情罚款。过路费面板与资产操作拆分不得修改 `transferIsPlotFine`、`estimatedTransferAmount`、转账请求体或任何剧情罚款计算。过路费仍按现有规则计算，且不会套用剧情罚款减免。

## 测试

- Playwright：确认落点为他人地产时，独立过路费模块显示落点信息而非地产选择器，请求路径只指向该落点。
- Playwright：资产操作的操作类型列表不再包含“支付过路费”。
- Playwright：无确认落点、无主或自有落点、抵押地产、冷宫地主及已结算时，过路费模块保留、按钮禁用且显示对应原因。
- Playwright：快捷模块顺序为“购买 / 建造”“支付过路费”“资产操作”。
- 回归：现有沈眉庄剧情罚款转账测试继续通过，证明减免逻辑未受影响。

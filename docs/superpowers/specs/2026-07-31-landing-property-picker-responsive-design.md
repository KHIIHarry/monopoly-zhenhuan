# 声明地点地产选择器响应式优化设计

## 目标

在不改变 `LandingPropertyCardPicker` 数据、搜索筛选能力、落点选择行为和父组件状态管理的前提下，优化声明地点弹层的桌面双列布局与移动端信息密度。修复红色选择轮廓被滚动区域裁切的问题，并确保 375px、390px、430px 宽度下卡片不贴边、不溢出、不发生按钮异常换行。

本次只调整声明地点弹层相关样式及样式契约测试。地产浏览模式继续复用同一组件，但不随本次声明地点专属尺寸规则改变。

## 问题原因

- 选中卡使用 `3px` 红色外轮廓和 `2px` 外偏移，总共需要至少 `5px` 的外部绘制空间。
- 声明地点的地产网格同时是纵向滚动容器，但现有内边距只有 `3px`，因此最外侧红色轮廓会被裁切。
- 通用操作弹层宽度上限为 `760px`，无法稳定容纳两张地产卡、卡间距和轮廓安全区。
- 移动端继续使用桌面的 `220px` 折叠卡高度、字号和间距，导致卡片纵向过重，并且弹层贴近屏幕边缘。

## 布局方案

### 选择轮廓

保留现有外置红色轮廓、红勾和角色主题色左边框。声明地点滚动网格的四周内边距调整为 `6px`，为轮廓留下完整空间，不把红框改成可能覆盖主题边框的内描边，也不增加新的 DOM 包装层。

### 桌面端

- 声明地点弹层最大宽度调整为约 `840px`，同时受视口宽度限制。
- 视口宽度达到 `700px` 时，声明地点网格固定为两个等宽列，一排展示两张卡。
- 桌面折叠卡继续保持现有 `220px` 高度，避免无关视觉变化。
- 网格维持固定列间距，单张筛选结果只占一列，不横向拉伸占满整行。

### 移动端

- 小于 `700px` 时回退为单列。
- `430px` 及以下时，声明地点弹层左右各保留 `8px` 页面间距，内容区使用约 `12px` 横向内边距。
- 折叠卡固定高度约 `174px`，仅通过逐项调整内边距、字号、行距和元素位置实现，不使用 `transform: scale()` 或整体缩放。
- 卡片内边距收紧至约 `12px 10px 12px 14px`；标题约 `18px`，辅助标签约 `11px`，核心金额和所有者约 `13px`，玩家昵称约 `10px`。
- 基础信息网格缩小行间距，并保留两列结构，以减少纵向堆叠。
- 搜索框高度约 `40px`，字体保持 `16px`，避免 iOS 聚焦缩放。
- 筛选按钮高度约 `40px`，缩小视觉填充但保留足够触控面积；按钮可紧凑换行，文字保持单行。
- 卡片间距约 `10px`。空结果虚线框与移动端折叠卡保持相同宽高。
- 选中勾、产权标签、冷宫提示和抵押印章按移动端卡片重新定位，不能遮挡标题、金额或卡片边界。

展开卡片仍按详情内容自然增高，不强制使用折叠卡高度。声明地点模式本身不展开详情，地产浏览模式现有展开逻辑保持不变。

## 作用范围

响应式尺寸通过 `.landing-action-sheet` 限定在声明地点弹层内。共享组件的搜索、角色筛选、排序、产权标签、抵押、冷宫、所有者和选择逻辑全部保持不变。不新增组件、不修改 API、不修改数据库，也不引入新的设计变量。

## 测试与验收

先补充样式契约测试，再修改样式：

- 声明地点滚动网格具有至少 `6px` 的轮廓安全内边距；
- 声明地点弹层在桌面端具有约 `840px` 宽度上限；
- `700px` 及以上固定两列，较窄视口固定一列；
- `430px` 及以下具有页面边距、紧凑卡片高度、紧凑字号和统一控件高度；
- 空结果框与折叠卡在移动端保持同高；
- 规则只作用于声明地点弹层，不改变地产浏览模式的桌面卡片尺寸。

完成样式契约测试后运行共享组件测试、Web 类型检查和生产构建。按项目约束使用 Docker Compose 提供系统，在 `http://localhost:3000` 分别检查桌面、375px、390px、430px 视口，确认双列布局、选中框完整性、页面边缘间距、搜索与筛选换行、卡片尺寸和滚动区域均符合要求。

# 房间配置生命周期设计

日期：2026-07-29

## 目标

管理页面始终可以进入。房间开局后，按配置对游戏历史和运行时行为的影响分级，而不是整体锁定配置。

## 配置分类

始终可修改：

- 房间名称
- 可见性
- 房间密码

仅大厅可修改：

- 骰子模式
- 初始资金
- 起点奖励
- 人物技能

运行时可修改：

- 中途加入
- 转帐审批

终局房间仍不可修改任何配置或密码。

## 自动跳过

移除 `autoSkipTurn` 配置及其所有 API、界面、类型、数据库列和测试夹具。电子骰子模式固定在创建下一可行动回合时消耗一次停轮并跳过；实体骰子模式不管理回合和停轮消费。该行为当前已由回合服务实现，不能由配置改变。

## 后端行为

`PATCH /api/admin/rooms/:id` 继续接受部分更新，但在非大厅状态拒绝尝试修改 `diceMode`、`initialBalance`、`startReward` 或 `skillEnabled`，返回既有的 `ROOM_CONFIG_LIFECYCLE_CONFLICT`。名称、可见性、`allowMidgameJoin` 与 `transferApprovalRequired` 在进行中房间可更新。

加入操作在创建新成员资格时读取当时的 `allowMidgameJoin`。修改开关不会移除、冻结或改变已存在的成员资格。

创建玩家转帐请求时读取当时的 `transferApprovalRequired`，决定该新请求是直接执行还是进入审批流程。修改开关不会重写、自动批准、撤销或改变已有请求。

## 管理界面

详情刷新后以房间状态计算锁定字段。进行中房间的大厅专属控件使用原生 `disabled`，显示灰色状态，并紧邻控件显示“开局后锁定”。名称、可见性、运行时开关和密码保持可操作。

保存按钮仅在草稿包含可提交的差异且不在保存中时可用。保存前后或实时刷新发现房间由大厅进入进行中时，页面以服务端详情覆盖草稿，并显示“房间已开始，部分规则已锁定”。

## 测试

- API 集成测试：进行中房间拒绝大厅专属字段，允许名称、可见性和两个运行时开关。
- 服务集成测试：中途加入和转帐审批变更只在变更后的新操作中读取，不追溯已有成员或请求。
- 浏览器测试：进行中房间的四个锁定字段确实禁用并展示说明，运行时开关仍可保存，保存按钮在没有可提交差异时禁用。
- 回归测试：电子骰子自动跳过与实体骰子手动停轮行为不依赖已移除的字段。

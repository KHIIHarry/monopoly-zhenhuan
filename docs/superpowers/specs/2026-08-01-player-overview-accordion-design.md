# 玩家端房间资产概览设计

## 目标

为玩家端新增“概览”导航，让所有玩家都能查看当前房间的玩家与资产情况。同时将银行端概览的玩家状态列表改为相同的只读 Accordion，保证两端的玩家资产展示和地产详情完全一致。

## 界面范围

- 玩家端导航顺序为“首页”、“概览”、“地产”、“账本”。
- 玩家端“概览”显示当前玩家人数与所有玩家列表。
- 银行端保留现有“概览”导航、房间状态、开局、当前轮次和待审批功能，仅将其玩家列表替换为共享 Accordion。
- 概览只用于查看，不提供余额、地产、建筑或所有者的编辑操作。

## 玩家资产状态

每位玩家的状态条显示：

- 昵称。
- 当前现金，直接使用快照中的 Player.balance。
- 地产数量，即 ownerId 等于该玩家 ID 的地产数量。
- 普通建筑数量，仅累加等级为 1 至 4 的已持有地产的 level。
- 大宫殿数量，每块 level === 5 的已持有地产计为 1 座。

概览不计算也不显示货币化的“总资产”。现金、地产数量、普通建筑数量和大宫殿数量共同构成该页的资产概况；现有结算价值和排名逻辑不变。

## Accordion 与共享组件

- 新增一个共享的玩家资产 Accordion，由玩家端概览和银行端概览调用。该组件只负责玩家状态和展开状态，不实现地产卡片。
- 点击玩家状态条在当前页展开或收起详情，不进行路由跳转。
- Accordion 一次最多展开一位玩家；触发控件提供 aria-expanded 和关联的详情区域，并支持键盘操作。
- 展开区直接渲染现有 LandingPropertyCardPicker，使用 mode="browse"，并将 properties 设为按当前玩家 ownerId 过滤后的地产数组。
- 玩家端概览和银行端概览向统一地产组件传入相同数据形式，不传入任何编辑回调。
- 不新增地产卡片、地产详情、地产空状态或页面专用地产展示组件，也不复制 LandingPropertyCardPicker 内部标记。

## 数据与实时同步

- 使用现有房间快照中的 players 和 properties，在前端派生地产与建筑数量；不新增 API、数据库字段或持久化的概览状态。
- 玩家视图的快照已包含房间内所有可玩玩家和全部地产；概览不扩大玩家的账本、请求或审计日志可见范围。
- 继续使用现有 Socket.IO 房间版本通知、stateVersion 比较和 REST 完整快照重拉机制。余额、产权或建筑状态变更后，两端都从新快照重新派生概览数据。
- 不新增定时轮询，不使用 Socket 事件负载作为最终资产状态。

## 空状态与兼容性

- 玩家没有地产时，展开区仍调用 LandingPropertyCardPicker 并传入空数组，由该统一组件渲染现有空状态。
- 玩家或地产随新快照变化时，不再存在的展开玩家会自动收起，不保留失效的派生资产数据。
- 保留现有玩家端“地产”页、银行端“地产”页和声明落点的统一地产组件用法。

## 验证

- 资产派生单元测试：覆盖无地产、1-4 级普通建筑累加、5 级只计入大宫殿、抵押地产仍计入地产和建筑数量。
- 组件测试：覆盖玩家状态文案、只展开一位玩家、以该玩家地产数组调用 LandingPropertyCardPicker mode="browse" 以及无地产空状态。
- 集成契约测试：覆盖玩家导航新增“概览”，玩家端与银行端调用同一玩家资产 Accordion，且没有新的地产展示组件。
- 浏览器测试：在玩家端和银行端分别打开同一玩家，验证 Accordion 原地展开、地产卡可继续展开详情、页面无编辑入口，并检查移动端与桌面端布局。
- 运行相关 Vitest、全量类型检查、ESLint、生产构建，并通过 Docker Compose 应用栈以 PLAYWRIGHT_EXTERNAL_STACK=1 运行相关 Playwright 用例。

## 非目标

- 不修改结算阶段的总财富计算、排名或地产价值口径。
- 不新增玩家账本、审批请求或银行审计日志的可见权限。
- 不新增概览搜索、排序、编辑、跳转、轮询或独立地产详情页。

# 房间配置保存反馈设计

## 目标

让超级管理员在房间管理中修改配置后，只有在服务端持久化且重新读取的配置与提交内容一致时，才能看到明确的成功反馈；刷新页面后应继续显示保存后的值。

## 方案

沿用现有 `PATCH /api/admin/rooms/:id` 与详情读取接口。保存期间，保存按钮显示加载图标与“正在保存”，并阻止重复提交。写入成功后刷新后台聚合数据与当前房间详情；将所有已提交的房间配置字段与详情中的 `configuration` 逐项核对。核对通过时，以成功状态替换按钮文案，并在配置区域显示短暂成功提示；核对失败或详情刷新失败时，不显示成功状态，保留编辑值并显示错误。

## 非目标

不改变数据库结构、现有 API 请求格式或正在进行房间的配置限制。

## 验收

- 保存请求期间可见加载状态且保存按钮不可再次触发。
- 保存后重新读取的配置与输入一致时，显示“已保存并生效”。
- 刷新详情后继续显示服务端保存的值。
- 回读不一致或失败时，不能显示成功反馈。

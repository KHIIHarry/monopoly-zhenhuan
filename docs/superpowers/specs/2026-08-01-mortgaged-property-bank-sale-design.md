# 抵押地产卖回银行与赎回手续费配置设计

## 目标

允许玩家将没有建筑的抵押地产直接出售给银行，无需先单独赎回。出售仍通过现有申请与银行审批流程完成，并在批准后原子更新资金、产权和抵押状态。

同时将房间已有的 `redemptionFee` 暴露为可配置规则：创建房间时可填写，管理员可在大厅阶段修改，游戏开始后锁定。该值为大于等于 `0` 的整数，默认 `200` 两。

## 规则

### 未抵押地产卖回

未抵押且没有建筑的地产继续按现有规则卖回银行：

```text
最终售价 = 地产购买价
```

### 抵押地产卖回

抵押地产已经向玩家发放过抵押款，因此直接卖回时先扣除已获得的抵押款，再扣除房间配置的赎回手续费：

```text
当前剩余价值 = 地产购买价 - 地产抵押价
最终售价 = max(0, 当前剩余价值 - 房间赎回手续费)
```

最终售价最低为 `0` 两，不允许出售操作反向扣减玩家余额。

抵押地产仍必须先出售全部建筑。当前数据约束不允许地产同时处于抵押和有建筑状态，服务端仍需保留建筑等级为 `0` 的校验。

### 玩家间交易

玩家间交易规则不变：

- 抵押地产不得交易；
- 有建筑的地产不得交易；
- 买家确认和银行最终审批流程保持不变。

## 配置生命周期

复用数据库现有的 `Room.redemptionFee` 字段，不新增数据列或迁移。

- 创建房间页面新增“赎回手续费”数字输入框；
- 默认值为 `200`；
- 支持 `0`；
- 只接受大于等于 `0` 的整数；
- 管理员房间配置页面显示并允许修改该字段；
- 仅房间处于 `LOBBY` 时允许修改；
- 游戏开始后输入框锁定，服务端也拒绝修改；
- 创建房间、管理员详情和管理员更新接口均纳入该字段；
- 游戏快照继续返回该字段，作为玩家端展示与预览的数据来源。

## 玩家端交互

“资产操作”中的“卖给银行”应列出本人所有没有建筑的地产，不再排除抵押地产。玩家间交易的候选列表继续排除抵押地产。

选择抵押地产时，结算预览显示按服务端同一公式推导的最终售价。点击“确认提交”后先打开现有样式的 `ConfirmDialog`，内容为：

```text
该地产处于抵押状态，按照游戏规则，直接出售将扣除 {赎回手续费} 两赎回费用，是否继续？
```

其中 `{赎回手续费}` 使用当前房间配置值；配置为 `0` 时明确显示“扣除 0 两赎回费用”。玩家取消时不创建申请，玩家确认后才向服务端提交申请。

未抵押地产保持现有直接提交行为，不增加该警告弹窗。

申请成功后继续使用现有本地 toast：“资产操作已提交银行审批”。银行拒绝和批准后的资金通知继续走现有实时 toast 队列，不引入新的通知通道或展示机制。

## 服务端审批与数据一致性

创建 `SELL_PROPERTY_TO_BANK` 请求时，由服务端读取地产定义、抵押状态和房间赎回手续费并计算金额，不接受客户端提交的最终售价。

申请创建后沿用现有地产锁，防止审批前发生并发资产操作。银行批准时必须再次校验：

- 申请玩家仍是地产所有者；
- 地产建筑等级仍为 `0`；
- 地产仍由该申请持有锁；
- 地产抵押状态与申请创建时一致；
- 请求内持久化的售价作为审批结算金额。

银行批准后，在同一数据库事务中：

1. 按请求金额增加玩家余额并写入账本；
2. 将地产 `ownerPlayerId` 清空，表示银行回收并恢复无主；
3. 将 `mortgaged` 设置为 `false`；
4. 清除 `lockedByRequestId`；
5. 增加地产版本；
6. 将申请标记为已执行并记录可撤销事务。

事务元数据继续保存 `propertyBefore` 和 `propertyAfter`。若银行撤销该事务，现有撤销机制应恢复原所有者、原抵押状态和玩家出售前余额。

银行拒绝申请时只解锁地产，不改变产权、抵押状态或余额，并沿用现有拒绝 toast。

## Toast 兼容

抵押地产卖回产生一条正数账本记录，类型继续为 `SELL_PROPERTY_TO_BANK`。现有 `fundsCommitted` 通知链路据此向出售玩家和银行会话发送资金 toast；不修改 FIFO、去重、显示时长或受众隔离规则。

售价为 `0` 时不产生非零资金 toast，保持现有“零金额事务不发送资金通知”的业务规则。申请审批、产权回收和抵押清除仍正常完成，并通过房间快照实时刷新体现。

## 测试范围

### 房间配置

- 创建房间默认手续费为 `200`；
- 创建房间可填写 `0` 和其他非负整数；
- 负数和非整数被接口拒绝；
- 管理员可在大厅阶段修改手续费；
- 游戏开始后管理员修改被服务端拒绝；
- 创建页面与管理员页面正确显示默认值、保存值和开局后锁定状态。

### 出售申请与审批

- 未抵押地产卖回价格仍等于购买价；
- 抵押地产请求金额等于 `购买价 - 抵押价 - 手续费`；
- 手续费为 `0` 时公式正确；
- 手续费高于剩余价值时请求金额为 `0`；
- 有建筑地产仍不能卖回；
- 抵押地产可创建卖回申请并被正确锁定；
- 银行批准后玩家获得请求金额，产权清空、抵押清除、锁清除；
- 银行拒绝后资产状态和余额不变；
- 撤销批准后恢复玩家余额、产权和原抵押状态；
- 抵押地产仍不能进入玩家间交易申请。

### 玩家端与通知

- “卖给银行”候选包含没有建筑的抵押地产；
- 玩家间交易候选仍排除抵押地产；
- 抵押地产提交前显示包含当前手续费的确认提示；
- 取消确认不会发送请求，确认后进入银行审批；
- 正数售价批准后继续触发玩家和银行资金 toast；
- 零售价保持现有不发送资金 toast 的规则。

## 非目标

- 不新增独立的“抵押地产出售手续费”；
- 不允许带建筑地产直接出售；
- 不改变玩家间地产交易规则；
- 不改变银行审批、拒绝、撤销或 toast 队列架构；
- 不允许游戏开始后修改赎回手续费；
- 不接受客户端指定卖回最终金额。
